# Portfolio Dashboard v5.2 — product development plan

Status: **in development**  
Frozen financial methodology: **5.1**  
Frozen reference: `frozen/v5.1.0` / `92ca8f61bdfd25c5733357789ed63425ec61f292`

## Objective

v5.2 is a product/UX and robustness iteration built on top of the validated v5.1 financial engine.

The target workflow is:

> refresh → understand what changed → decide where the next contribution should go

The goal is not to add many indicators. Priority remains user value, iPhone simplicity, financial reliability and maintainability.

## Frozen methodology guardrail

The following conventions remain unchanged unless a future PR explicitly declares a methodology-version change:

- main portfolio scope = Compte-titres + PEA;
- crypto remains outside main performance and benchmark comparison;
- cash and private markets remain outside main performance;
- canonical main cash-flow mapping;
- economic P&L convention;
- XIRR convention and 365-day basis;
- forward matched-flow MSCI World / S&P 500 methodology;
- benchmark checkpoint semantics;
- strict temporal cutoff at the official PDF snapshot date;
- snapshot-only historical observations with no daily interpolation presented as observed data.

A package/application version may become 5.2 while the financial methodology remains 5.1.

## v5.2 product priorities

1. Reduce the normal iPhone workflow to one deliberate refresh/save action.
2. Make each new snapshot explain performance since the previous saved snapshot, separately from contributions/withdrawals.
3. Make rebalancing useful for the next contribution without requiring sales.
4. Make folder source selection robust to re-downloaded older files.
5. Add browser-level integration coverage before simplifying UI wiring.
6. Improve sparse-history readability as real snapshots accumulate.
7. Reduce duplicate parsing and DOM-coupled UI integration where it improves maintainability without changing behavior.

## Planned PR sequence

### PR 5.2-01 — documentation and guardrails

- record the frozen v5.1 reference;
- remove stale documentation that still describes the market adapter/provider as future or unvalidated;
- document package-version vs methodology-version separation.

### PR 5.2-02 — browser integration coverage

Protect the critical user journey before UI refactoring:

- import synthetic Trade Republic sources;
- render the dashboard;
- verify Overview / allocation / rebalancing mounting;
- save a derived snapshot;
- reload and verify local history continuity.

No personal source fixture may be committed.

### PR 5.2-03 — robust folder source selection

Prefer source-semantic recency where reliably available rather than filesystem `lastModified` alone. Preserve clear failure behavior and prevent accidental regression to an older snapshot.

### PR 5.2-04 — one-tap refresh and save

The primary iPhone action should explicitly analyze and save the resulting derived snapshot in one workflow. Manual analysis without persistence remains available as a secondary diagnostic path.

### PR 5.2-05 — performance since previous snapshot

Using the frozen canonical cash-flow convention, derive period economic P&L between two saved official snapshots:

`period_pnl = terminal_value - starting_value + sum(canonical_cashflows_in_period)`

Show contributions/withdrawals separately. Do not introduce reconstructed daily NAV or daily TTWROR.

### PR 5.2-06 — contribution-first rebalancing

Given a user-specified new contribution, calculate buy-only allocation guidance and projected post-contribution weights. Do not execute orders and do not silently assume selling.

### PR 5.2-07 — allocation and sparse-history UX

- explicitly label Top 1 / Top 3 / HHI as line-level concentration;
- improve touch/readability of the observed sparse history;
- keep missing benchmark points missing rather than interpolating them.

### PR 5.2-08 — internal UI simplification

Only after integration coverage exists:

- reduce reparsing of the same PDF;
- reduce dependence on `MutationObserver` and heading-text discovery;
- move toward a shared typed UI state/event interface;
- preserve rendered behavior and privacy boundaries.

## Explicit non-goals for v5.2

Unless a concrete problem emerges, v5.2 does not include:

- daily reconstructed NAV;
- TTWROR backfill;
- volatility, Sharpe or drawdown inferred from sparse irregular snapshots;
- historical price backfill for every portfolio instrument;
- tax-lot / capital-gains engine;
- arbitrary-symbol market-data backend;
- news-driven trade recommendations inside the PWA;
- automatic brokerage order execution;
- replacement of EODHD or the current Cloudflare Worker architecture without an observed reliability/cost problem.

## Release gate

Before v5.2 is frozen:

- all existing v5.1 financial tests remain green;
- new browser integration tests cover the primary workflow;
- GitHub Pages build/deploy remains green;
- Worker smoke/config/dry-run checks remain green;
- manual iPhone validation confirms refresh/save, persistence, offline reopening and benchmark rendering;
- `docs/RELEASE_V5.2.md` records whether the financial methodology remains 5.1 or explicitly changes.
