# Portfolio Dashboard v5.2 — product development plan

Status: **implementation complete — release candidate validation**  
Application/package target: **5.2.0**  
Frozen financial methodology: **5.1**  
Frozen reference: `frozen/v5.1.0` / `92ca8f61bdfd25c5733357789ed63425ec61f292`

## Objective

v5.2 is a product/UX and robustness iteration built on top of the validated v5.1 financial engine.

The target workflow is:

> refresh → understand what changed → decide where the next contribution should go

The goal is not to add many indicators. Priority remains user value, iPhone simplicity, financial reliability and maintainability.

## Frozen methodology guardrail

The following conventions remain unchanged:

- main portfolio scope = Compte-titres + PEA;
- crypto remains outside main performance and benchmark comparison;
- cash and private markets remain outside main performance;
- canonical main cash-flow mapping;
- economic P&L convention;
- XIRR convention and 365-day basis;
- forward matched-flow MSCI World / S&P 500 methodology;
- benchmark checkpoint semantics;
- strict temporal cutoff at the official PDF snapshot date;
- snapshot-only historical observations with no daily interpolation presented as observed data.

Application version 5.2 therefore continues to use **financial methodology 5.1**.

## Implemented PR sequence

### PR #39 / 5.2-01 — documentation and guardrails

Recorded the immutable v5.1 baseline, clarified application-version vs methodology-version separation, and updated stale Worker/EODHD documentation.

### PR #40 / 5.2-02 — built UI integration coverage

Added a smoke test against the built Vite artifact using synthetic-only state. It protects Overview composition, extension bindings and IndexedDB history continuity.

### PR #41 / 5.2-03 — robust folder source selection

Folder refresh now prefers actual PDF snapshot date and CSV transaction coverage rather than filesystem timestamps alone, rejects accidental regression to an older saved snapshot, and uses one authoritative parsed snapshot across the UI.

### PR #42 / 5.2-04 — one-tap refresh and save

The primary iPhone action is now `Actualiser et enregistrer`. Manual `Analyser sans enregistrer` and manual snapshot save remain available as secondary/fallback paths.

### PR #43 / 5.2-05 — performance since previous snapshot

Added flow-adjusted economic P&L between compatible saved snapshots, separately from net invested flows and raw value change. No daily NAV or TTWROR reconstruction is introduced.

### PR #44 / 5.2-06 — contribution-first rebalancing

Added deterministic buy-only guidance for a user-entered next contribution, including projected weights and drift. The planner does not execute orders or model whole-share, fee or tax constraints.

### PR #45 / 5.2-07 — allocation and sparse-history UX

Clarified line-level concentration (`Top 1 ligne`, `Top 3 lignes`, `HHI lignes`) and added touch-friendly exact-point inspection to the observed sparse history.

### PR #46 / 5.2-08 — internal UI simplification

Replaced five independent script entry points with one deterministic application bootstrap, removed unnecessary startup observers where safe, and reduced panel-order coupling while retaining runtime observers needed for rerenders.

## Explicit non-goals retained

v5.2 does not include:

- daily reconstructed NAV;
- TTWROR backfill;
- volatility, Sharpe or drawdown inferred from sparse irregular snapshots;
- historical price backfill for every portfolio instrument;
- tax-lot / capital-gains engine;
- arbitrary-symbol market-data backend;
- news-driven trade recommendations inside the PWA;
- automatic brokerage order execution;
- replacement of EODHD or the current Cloudflare Worker architecture without an observed reliability/cost problem.
